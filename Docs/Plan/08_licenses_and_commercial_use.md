# 08. ライセンスと商用利用（有償配布）の調査

本ドキュメントは、[02_tech_stack.md](02_tech_stack.md) で採用されている技術スタックについて、**商用利用および有償での .exe 配布（BOOTH、Gumroad、Steam 等での販売）が可能か** を法務・ライセンスの観点から調査・整理したものです。

また、**「ソースコードを GitHub で公開する」** という開発方針を踏まえ、採用技術のライセンス義務や自作コードのライセンス選定戦略についても解説します。

---

## 1. 調査結果の総括（結論）

> [!NOTE]
> **結論：有償での .exe 配布は「完全に可能」です。何ら法的・契約上の障壁はありません。**

- **パーミッシブ・ライセンスで統一**：採用しているすべてのライブラリおよびフレームワーク（Tauri 2、Svelte 5、Rust クレート群など）は、**MIT**、**Apache-2.0**、**BSD-3-Clause**、**zlib** などの商用利用・有償再配布が無制限に許可された「パーミッシブ（寛容型）ライセンス」を採用しています。
- **感染性コピーレフト（GPL/AGPL 等）の不在**：バイナリ配布時にプロジェクト全体のプロプライエタリ性を強制解除したり、想定外の派生物公開義務を負わせるような強いコピーレフトを持つライセンスは一切含まれていません。
- **ソースコード公開方針との親和性**：ソースコードを GitHub で公開する方針であるため、将来的に弱コピーレフト（MPL-2.0 等）のライブラリが加わったとしても容易に要件を満たせます。

## 2. 採用技術のライセンス一覧と商用利用条件

| **Svelte 5** | MIT | **可能** | 著作権表示およびライセンス条文の表示 |
| **TypeScript** | Apache-2.0 | **可能** | コンパイラツール。ビルド後の JS 出力にはライセンス縛りなし |
| **Vite** | MIT | **可能** | ビルドツール。成果物への直接的義務なし（慣例として表記に含めてもよい） |
| **Bits UI**（ヘッドレス UI） | MIT | **可能** | 著作権表示およびライセンス条文の表示 |
| **WebGL2 / GLSL** | Web 標準仕様 | **可能** | 標準 API。ライセンス制約なし（シェーダーコードは自作著作物） |

### 2.3 ビルド・配布ツール・アセット（想定されるもの）

| 項目 | ライセンス | 有償配布の可否と注意事項 |
|---|---|---|
| **NSIS** (インストーラ生成) | zlib/libpng, bzip2, CPL 等の複合 | **可能**。NSIS のライセンス条項により、NSIS でビルドされたインストーラ exe は商用・プロプライエタリを含め任意のライセンスで有償配布可能 |
| **UI フォント**（Inter, Noto Sans 等） | SIL Open Font License 1.1 (OFL) | **可能**。フォント単体での販売は禁止だが、**アプリに内包・同梱してアプリとして有償販売することは明確に許可**されている |
| **UI アイコン**（Lucide 等） | ISC または MIT | **可能**。ライセンス表示を含めること |

## 3. 有償配布時に順守すべき義務と実務対応

有償で .exe（ポータブル版またはインストーラ版）を配布・販売するにあたり、法的に必須となる対応は以下の **2 点のみ** です。

### 3.1 ライセンス表記（サードパーティ・クレジット）の同梱

MIT、Apache-2.0、BSD-3-Clause は共通して **「再配布物（バイナリ配布を含む）に、著作権表示およびライセンス条文を含めること」** を条件としています。

#### 実務での対応方法（2 つのアプローチ）
1. **アプリ内の About 画面に表示する（推奨）**
   - アプリのメニューバーや設定画面に「About / ライセンス情報」ダイアログを設け、サードパーティライセンス一覧をスクロール表示できるようにします。
   - ポータブル単体 exe で配布する場合でも、exe 内部にライセンス情報が完結するため最も安全で親切です。
2. **同梱テキストファイルに記載する**
   - 配布用 zip やインストーラに `THIRD_PARTY_LICENSES.txt`（または `LICENSE.txt`）を同梱します。

#### CI による自動化（[06_build_and_distribution.md §7](06_build_and_distribution.md#7-ライセンス表記) の具体化）
手作業で依存ライブラリのライセンスを収集するのはミスが発生しやすいため、以下のツールでビルド時に自動生成します。

- **Rust 側**：`cargo-about` を使用して `Cargo.lock` に含まれる全依存関係の著作権者・ライセンス本文を HTML/JSON/Markdown で生成。
- **フロントエンド側**：`license-checker` または `license-checker-webpack-plugin` 等を使用して `pnpm-lock.yaml` の依存関係を抽出。
- これらを 1 つの JSON または Markdown にまとめ、Svelte 側の About ダイアログに読み込ませます。

### 3.2 フォント（SIL Open Font License 1.1）の留意点

UI に Inter や Noto Sans などの Google Fonts（OFL 1.1）を採用する場合：
- **禁止事項**：フォントファイル（.woff2, .ttf 等）を単体で抽出して「フォント製品」として販売すること。
- **許可事項**：Matcap Maker アプリケーションの描画用リソースとして exe やアセット内にバンドルし、アプリ全体を有償販売すること（規約上明確に許可されています）。
- **必須事項**：フォントの著作権表示および OFL 1.1 ライセンス本文をアプリ内または同梱ドキュメントに記載すること。

## 4. 「ソースコード公開 ＋ 有償 exe 配布」のライセンス戦略

「ソースコードは GitHub で公開し、コンパイル済み .exe は BOOTH や Gumroad、Steam 等で有償配布する」というモデルは、オープンソース界隈で **「バイナリ有償配布モデル（Open Source / Paid Binaries）」** や **「デュアル／ソースアベイラブルモデル」** として確立されています（例：Aseprite、Blender、Ardour など）。

自作コードの公開ライセンスとして、開発者の意図に合わせて 3 つの選択肢があります。

### パターン A: 完全オープンソース（MIT または Apache-2.0）
- **概要**：ソースコードもパーミッシブライセンスで公開する。
- **法的位置付け**：
  - 開発者は公式バイナリ（exe）のサポート・パッケージング代として有償販売できます。
  - ただし、第三者が GitHub のソースを取得して自前でビルドし、「無料で再配布する」ことや「別名で再販売する」ことも法的に許容されます。
- **向いているケース**：コミュニティからの貢献（プルリクエスト）を最大限募りたい場合。「ビルドの手間を省く」「自動更新や安心感」「開発者への応援（寄付的意味合い）」を有償 exe の価値とする場合。

### パターン B: コピーレフト型オープンソース（GPLv3）
- **概要**：自作コードを GPLv3 で公開する。
- **法的位置付け**：
  - 開発者は exe を有償販売できます（GPL は有償販売を明示的に認めています）。
  - 第三者がビルドして再配布する場合、その派生物も GPLv3（ソースコード公開義務付き）でなければならず、クローズドソースで商用製品に組み込むことはできなくなります。
- **注意点**：MIT/Apache-2.0/BSD-3-Clause のライブラリと GPLv3 コードのリンクは法的に互換性があり問題ありません。

### パターン C: ソースアベイラブル（非商用ライセンス / 独自規約）★ BOOTH 個人開発で人気
- **概要**：GitHub 上でコードは誰でも閲覧・個人ビルド・PR 可能とするが、**「第三者による無断での商用利用・再配布・再販売を禁止する」** 規約（例：PolyForm Noncommercial、BSL、Aseprite 型 EULA）を適用する。
- **法的位置付け**：
  - 著作権者（本人）だけが唯一の「商用版 .exe の公式販売権」を持ちます。
  - 第三者がビルドした exe を BOOTH 等で勝手に転売・無料配布することを法的に差し止められます。
- **向いているケース**：有償 exe の販売収益を確実に保護しつつ、透明性のためにソースコードを公開したい場合。

> [!TIP]
> **推奨アプローチ**：
> 「有償 exe を購入してもらうインセンティブ」を守りたい場合は **パターン C（ソースアベイラブル規約）** または **パターン A + 商標の保護（アプリ名・ロゴの無断利用禁止条項）** が適しています。
> 採用技術（Tauri/Svelte/Rust クレート群）はすべてパーミッシブであるため、上記 A, B, C のどのライセンスを自作コードに適用しても、採用ライブラリ側とのライセンス違反・競合は一切発生しません。

## 5. 将来の機能追加におけるライセンス注意点

今後プラグインや追加クレート・npm パッケージを導入する際、意図せぬライセンス感染や商用利用制限を防ぐためのガイドラインです。

1. **GPL / AGPL ライブラリの混入防止**：
   - 自作コードをパターン A や C で運用する場合、GPL/AGPL のライブラリをリンクするとライセンス矛盾が生じます。
   - 特に画像処理系（FFmpeg、GPL 版 libx264 等）を導入する際は、ライセンスが LGPL または GPL でないかを必ず確認してください。
2. **CC-BY-NC（非営利限定）アセットの除外**：
   - プリセット画像、法線マップ、matcap サンプルなどの素材を同梱する場合、クリエイティブ・コモンズの「NC（Non-Commercial）」マークがついている素材は有償配布アプリに同梱できません。商用利用可能な CC0、CC-BY、または自作アセットのみを使用します。
3. **Rust `exr` クレートの BSD-3-Clause 順守**：
   - `exr` クレートに含まれる BSD-3-Clause には「事前の書面による許可なしに、本ソフトウェアから派生した製品を推奨または宣伝するために、著作権者の名前を使用してはならない」という条項（第 3 条）があります。宣伝文句に「〇〇氏推奨」などの表現を使わない限り、通常の製品説明では何の問題もありません。

---

## 6. まとめ

- **有償 exe 配布の可否**：**〇 完全可能**（一切の制限なし）。
- **やるべきこと**：
  1. アプリ内の About 画面または同梱ドキュメントに、Tauri / Svelte / 採用クレートの著作権表示とライセンス条文（MIT/Apache/BSD）を載せる（CI で自動生成）。
  2. 自作コードの GitHub 公開時のライセンス（MIT / ソースアベイラブル等）を自身のビジネス方針に合わせて決定する。
