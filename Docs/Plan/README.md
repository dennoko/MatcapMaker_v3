# Matcap Maker リメイク計画

現行 v3（Python + PySide6 + PyOpenGL）の機能をすべて保ったまま、以下を目標に作り直すための計画書です。

- **柔軟で直感的な操作感**（プレビュー上での直接操作、Undo/Redo、プリセット、ドラッグ＆ドロップ）
- **軽量な動作**（起動の速さ、アイドル時 CPU 0%、編集中の再描画を最小限にする）
- **ビルドと配布のしやすさ**（署名なしの .exe 単体配布、コマンド 1 つでのビルド、CI での自動化）

既存の実装や技術選定はいったん前提から外し、ゼロから最適な構成を検討しています。

## 結論（要約）

| 項目 | 採用 |
|---|---|
| アプリシェル | **Tauri 2**（Rust 製の軽量ネイティブシェル + OS 標準の WebView2） |
| UI | **Svelte 5 + TypeScript + Vite** |
| 描画 | **WebGL2**（自前の薄いレンダラー。内部は RGBA16F）。将来 WebGPU に移行できる抽象を持たせる |
| ネイティブ処理 | Rust：ファイル I/O、PNG/EXR エンコード、設定の保存 |
| 配布物 | **ポータブル .exe 単体（約 10MB）**、必要に応じて NSIS インストーラも（どちらも署名なし） |
| ビルド | `pnpm tauri build` 一発。GitHub Actions（`windows-latest`）で自動リリース |

アーキテクチャ上の主な変更点：

1. **「マットキャップ空間」で生成し、プレビューとは分離する**。レイヤーは球体メッシュではなく、正規化された法線ドメイン（2D の円盤）上で評価します。球体・ノーマルマップ付き球体・任意メッシュでのプレビューは、生成結果を貼るだけの独立したビューになります。
2. **宣言的なレイヤー定義（スキーマ駆動）**。1 つのレイヤー定義から UI、シリアライズ、既定値、マイグレーション、uniform の割り当てをすべて自動で導きます。新しいレイヤーは「定義ファイル + GLSL 関数」の 2 ファイルだけで追加できます。
3. **コマンドベースの状態管理**。Undo/Redo、自動保存、クラッシュからの復旧を最初から組み込みます。
4. **差分レンダリング**。変更されたレイヤーから下だけを描き直し、ドラッグ中は解像度を下げて描き、静止したら高解像度で描き直します。
