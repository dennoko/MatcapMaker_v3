# 07. 開発ロードマップと移行計画

## Phase 0：技術検証のスパイク（1〜2 週間）
最大のリスクである「Tauri + WebView2 + WebGL2 で目標を満たせるか」を先に確かめる。

- [ ] Tauri 2 + Svelte 5 の骨組みを作り、CI で exe をビルドする
- [ ] マットキャップ空間で Solid、Spot、Fresnel と blend.glsl（全 12 モード）を実装する
- [ ] 差分レンダリングのキャッシュを実装し、10 レイヤーでスライダーを動かしたときの描画時間を計測する
- [ ] 4K の RGBA16F を読み戻し、生バイナリの IPC で Rust に渡して PNG にエンコードし、時間を計測する
- [ ] GPU の JFA パディングを実装し、現行 `export_padding.py` の出力と見比べる
- [ ] 計測：exe のサイズ、起動時間、アイドル時の CPU、メモリ（WebView2 のプロセスを含む）

**判断基準**：02 の非機能要件を概ね満たせば続行する。メモリや起動時間が大きく外れた場合は、次点案（egui + wgpu）への切り替えを検討する。レイヤー定義と GLSL はどちらの案でも流用できる。

## 移行計画

### 旧プロジェクトとの互換
- `LegacyV3Importer` を Phase 1 の必須項目にする。変換のルール：
  | 現行 | 新版 |
  |---|---|
  | `BaseLayer.base_color` | 最背面の `solidColor` レイヤー |
  | `BaseLayer.preview_mode`, `normal_*` | `ViewState.normalMap` |
  | `layers` の配列順（先頭 = 最背面） | 逆順（先頭 = 最前面） |
  | `blend_mode: "Soft Light"` | `blendMode: 'softLight'` |
  | `image_path`（絶対/相対） | アセットとして取り込み、`AssetId` で参照 |
  | 未知のレイヤー、未知のパラメータ | スキップして警告を一覧表示 |
- インポートした内容は新形式で保存し、元の `.json` は変更しない。

### 見た目の一致の検証
- 現行版で「レイヤー単体 × 代表的なパラメータ」の参照画像を書き出すスクリプトを用意する（`tests/` の既存の検証スクリプトを流用）。
- 新版では Playwright で同じ構成を描き、ピクセル差（PSNR / 最大誤差）で比較する。意図的に変えた点（パディングのアルゴリズム、色空間など）は差分として記録する。

### 並行運用
- リメイク版が Phase 1 を終えるまでは、現行 v3 の保守（バグ修正のみ）を続ける。
- リメイク版は別リポジトリ（または `v4` ブランチ）で開発する。

## リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| WebView2 のメモリが想定より大きい | 軽さの目標を満たせない | Phase 0 で計測する。次点案（egui + wgpu）に切り替えられるよう、コアの設計を移植可能にしておく |
| 古い GPU で `EXT_color_buffer_float` が使えない | 16F で描画できない | RGBA8 にフォールバックする経路を用意する（HDR 関連の機能だけを無効にする） |
| 現行の見た目を完全には再現できない | ユーザーが違和感を持つ | ゴールデン画像による比較と、`blendSpace` などの互換オプション |
| Rust と TypeScript の 2 言語をまたぐ開発コスト | 開発速度 | Rust 側は I/O とエンコードだけの薄い層に限定する（数百行規模） |
| 署名なしでの SmartScreen 警告 | 初めての人が離脱する | 手順の案内、ハッシュの公開、将来の署名の選択肢（06 参照） |
